violeTM

AI threat modeling, hosted or self-hosted

violeTM is an AI security architect. You describe your system in plain English, it builds a data-flow model (components, data flows, trust boundaries, assets), walks every element, and hands back a grounded STRIDE threat model: ranked findings, remediation, and mappings to real control catalogs. It also runs an AI-specific pass for LLM apps, a privacy pass, compliance mappings, and a full triage workflow, then lets you export the whole thing. Run it hosted or run it yourself. The only secret you ever have to supply is your own Anthropic API key.

Try it without installing anything

There's a hosted build on Vercel with a guest mode, so you can model a system without creating an account, and a /demo that opens a seeded, realistic sample report if you'd rather just look around first. One thing to know: the hosted demo is a shared, disposable public sandbox. Projects there are visible to anyone and it may get wiped at any time, so treat it as a place to kick the tires, not to keep anything. For real work, self-host it (below) and your data stays with you.

Model a system

Modeling is a conversation. You describe the system in plain English and keep talking: each message updates the structured model (its components, data flows, trust boundaries, and assets) rather than starting over. When you're ready, violeTM generates threats one structured pass per element, so coverage is explicit. A banner at the top of the report surfaces any element that failed instead of quietly dropping it.

Read the threat model

The project opens as two panes: a chat and sidebar rail on one side, the report on the other. The report leads with a banded risk-score meter, a summary of your input, and a data-flow diagram. Then it lays out every finding: the STRIDE category, the affected element, likelihood and impact (severity is likelihood times impact), a plain-English "what this means for you", and concrete remediation. Findings aren't free-form. They're constrained to a real control catalog, so each one carries OWASP ASVS (V1 to V13) and CWE ids, and the remediation is tagged the same way. Severity badges are color-coded and readable, and tooltips work by keyboard and tap, not just hover.

The diagram in the sidebar is a fit-to-width, legible thumbnail with a persistent "Click to expand". Expanding opens a real pan and zoom lightbox (wheel to zoom, drag to pan, pinch on touch, reset, close) shared by the sidebar and the report. The boxes are drawn with clean straight lines and the labels are set in a hand-drawn font (Excalifont), which keeps the diagram readable without looking like a stock stencil. Across the rest of the UI the type is Geist Sans and Mono.

An AI-specific pass for AI apps

If your system has an LLM in it, STRIDE alone misses the interesting parts. violeTM runs a dedicated pass over the OWASP LLM Top 10 (2025), LLM01 through LLM10: prompt injection, sensitive information disclosure, supply chain, data and model poisoning, improper output handling, excessive agency, system-prompt leakage, vector and embedding weaknesses, misinformation, and unbounded consumption. Same grounded findings, same remediation, aimed at the failure modes that are specific to AI systems.

Compliance and privacy

Alongside STRIDE, violeTM runs a LINDDUN privacy pass with its own actionable remediation. It also produces compliance mappings against OWASP ASVS, GDPR, SOC 2, and the Philippines Data Privacy Act of 2012, flagging requirements as "at_risk". These mappings are deterministic (no extra LLM call), so they're repeatable. Read them as a map of what to check, not a certificate (see the note at the end).

Triage, re-model, and track

A threat model is a living document, so findings have a lifecycle. Each one can be open, mitigated, accepted, transferred, or marked a false positive (that last state is there for exactly when the AI gets it wrong, so you can dismiss it on the record). You can assign an owner, a due date, and a justification. When the system changes, describe the change and re-model: violeTM shows a diff against the previous version and keeps a version timeline with a risk trend that tells you whether things got better, worse, or held flat.

Get the findings out

You can export the whole model as a Markdown report, or pull pieces: a prompt bundle, the diagram as SVG or PNG, an executive summary, and a GitHub issue export that links back to the finding. Each finding has a copy-prompt and a copy-fix button for pasting straight into your editor or agent. There's also a downloadable repo-rules .zip (CLAUDE.md, AGENTS.md, .cursorrules) built from your open findings, so your coding assistant starts out knowing what to avoid. And you can publish a public, read-only share link, with a revoke control for when you're done sharing.

Self-host it

violeTM is built on Next.js 16, React 19, Bun, and Tailwind 4, with Drizzle ORM over Postgres (Neon, plain node-postgres, or an embedded pglite). Auth is Clerk by default but swappable, including a single-user local no-auth mode. The AI is Claude native (Haiku 4.5 for extraction, Sonnet 5 for generation) with multi-provider support through the Vercel AI SDK, so you can point it at OpenAI, Google, or a compatible endpoint instead. Diagrams render with Excalidraw and mermaid.

The simplest way to run your own copy: you need Docker and an Anthropic API key, nothing else to install.

export ANTHROPIC_API_KEY=sk-ant-...
docker compose up

That starts the app and its database together, runs migrations on boot, and serves violeTM at http://localhost:3000 in local, no-login mode. Stop it with Ctrl-C and bring it back with the same docker compose up.

If you'd rather run from source with zero external services, use Bun with the embedded pglite database:

export AUTH_PROVIDER=local
export DB_DRIVER=pglite
export PGLITE_PATH=./.threatlens/db

bun install
mkdir -p ./.threatlens/db
bun run db:migrate:local
bun run dev

Set ANTHROPIC_API_KEY in your environment to turn on the AI features. Want a finished report without generating one? Seed the bundled sample with the dev server stopped:

bun run scripts/seed-sample.ts

Where the data goes

When you self-host in local mode, violeTM keeps everything in its own database on your machine and only talks to the AI provider you configured, using the key you supply, to do the modeling. No violeTM account, no telemetry. (The hosted demo is the exception, as noted above: it's a shared public sandbox, so don't put anything real there.)

A note on what this is and isn't

violeTM is a tool to help you think, not an authority. It isn't legal advice. The AI output is a lead to verify, not a certification, and it can be wrong, which is exactly why the false-positive state exists. The compliance packs are mappings that flag requirements as "at_risk"; they are not a certification against ASVS, GDPR, SOC 2, or the Philippines DPA. Use the findings to drive real review by a real person.

violeTM is going open source soon. If that's interesting to you, keep an eye on the GitHub.
